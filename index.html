Tenant isolation that fails closed

Many organisations share one platform. The database itself refuses cross-tenant reads, so a bug in application code cannot expose another customer's data.

Problem
Shared platform, zero tolerance for data leaks
Approach
Tenant passed explicitly; PostgreSQL row policies as the last line
Result
Isolation holds even when application code is wrong
Where
Independent build · education SaaS role

Identity federation and zero-downtime migration

Enterprises rarely have one login system. Federate what exists, then move users to a cloud provider in the background so nobody has to sign up again.

Problem
Several login systems, one expected experience
Approach
OIDC/SAML federation; SCIM connectors for bulk, auditable migration
Result
Single sign-on across the estate; migration with no re-onboarding
Where
IAM role, 2022 – 2025

Reliable event-driven integration

Services must share facts without losing, doubling or reordering them. The event is saved with the data, delivered in order, and absorbed if it arrives twice.

Problem
Cross-service updates that must never double-apply
Approach
Transactional outbox; ordered topics; dedupe by database constraint
Result
Redeliveries and replays are safe by construction

Independent build

How I work

Security and compliance are checkpoints, not afterthoughts.

    Understand the real problem and the rules it lives under.

  3. Build

    Small, reviewed changes; agents help, rules in the repo keep them honest.

  4. Verify

    Unit, integration and end-to-end tests through the real path.

    cross-tenant tests

  5. Ship
